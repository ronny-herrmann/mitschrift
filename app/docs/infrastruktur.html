Ein geschlossenes System auf einem Server in Deutschland: Aufnahme im Browser, alles Weitere – Spracherkennung, Sprechererkennung und die KI für Bereinigung und Protokoll – auf diesem einen Server. Es gibt keine externe KI-Schnittstelle und im Betrieb keinen Datenfluss nach außen.

Schaubild

Blaue Pfeile: Inhalte (Audio, Text) – nur zwischen Browser und Server und innerhalb des Servers. Graue gestrichelte Pfeile: ausgehende Verbindungen des Servers für Code und Modell-Dateien – ohne Nutzerdaten.

Die Bausteine in einem Satz

  • Browser: nimmt auf, zeigt an, speichert nichts dauerhaft.
  • Caddy: einziger Eingang von außen, sorgt für HTTPS mit automatisch erneuertem Zertifikat.
  • Instanz Test / Produktiv: die eigentliche Anwendung, zweimal getrennt – neue Versionen laufen erst im Test, dann nach Freigabe produktiv. Jede hat ihre eigene Datenbank.
  • Sprachmodell: Ministral 3 8B von Mistral AI (Apache-2.0, kostenfrei), einem französischen Anbieter. Wir nutzen nur die frei lizenzierte Modell-Datei; Mistral ist am Betrieb nicht beteiligt und erhält nichts.
  • GitHub: Ablage des Quellcodes. Der Server holt sich Änderungen selbst ab – GitHub kann nicht auf den Server zugreifen.

Vor- und Nachteile dieser Infrastruktur

Vorteile

  • Geschlossenes System: keine externe KI, kein Datenfluss in fremde Clouds oder Drittländer.
  • Arbeitsplatz braucht keine Leistung und keine Installation – läuft auf jedem Büro-PC und Handy.
  • Starke Modelle, weil zentral gerechnet wird: bessere deutsche Erkennung, schnell, keine Freezes.
  • Kein Modell im Browser-Cache – IT-Cache-Löschungen stören nicht.
  • Offene Lizenzen, 0 € Lizenzkosten, kein Anbieter-Lock-in; Modelle austauschbar.
  • Test und Produktiv getrennt; automatische, nachvollziehbare Auslieferung.
  • Umzug ins eigene Rechenzentrum jederzeit möglich (gleiches Skript).

Nachteile / Aufgaben

  • Betriebsverantwortung liegt bei uns: Updates, Überwachung, Störungen – kein Hersteller-Support mit Reaktionszeiten.
  • Wissen ist derzeit auf wenige Personen konzentriert; für den Regelbetrieb braucht es eine Vertretung und Betriebsdoku.
  • Ein Server = ein Ausfallpunkt. Fällt er aus, steht der Dienst (Daten gesichert, Neuaufbau ca. 15 Min.).
  • Audio wird zum Server übertragen (verschlüsselt) – bei reiner PC-Verarbeitung bliebe es am Platz.
  • Laufende Serverkosten statt Einmalkauf.
  • Bis zur städtischen Anmeldung (SSO) nur ein gemeinsames Passwort.
